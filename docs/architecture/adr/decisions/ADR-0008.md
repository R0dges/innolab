# ADR-0008 — Classer les comparaisons par paires avec Bradley–Terry

| Champ | Valeur |
|---|---|
| Domaine | Évaluation |
| Statut documentaire | Vérifié techniquement |
| Statut d’arbitrage | Non arbitré |
| Baseline vérifiée | `develop@2c0b7f82` |

## N0 — En clair

Un juré peut choisir le meilleur de deux projets. Juryza transforme l’ensemble de ces duels en forces relatives avec le modèle Bradley–Terry.

**Impact métier :** ce mode évite parfois la difficulté d’une note absolue, mais il lui faut assez de comparaisons bien réparties pour produire un classement crédible.

**Proposition de l’audit :** conserver la fonctionnalité, mais décider explicitement si elle produit le classement officiel, un indicateur secondaire ou une aide au jury.

## N1 — Ce que montre l’historique

- **Justification attestée :** `spec.md`, ajouté dans [`36e9b777`](https://github.com/R0dges/innolab/commit/36e9b7779cff456d8bead6ea887e5ff989e7a578), cite le mode pairwise comme bonus sans imposer Bradley–Terry.
- **Observé — première implémentation :** [`eecce74f`](https://github.com/R0dges/innolab/commit/eecce74f120fceb88128846d065cc1f6be304a01) ajoute le modèle, les routes et la page de comparaison.
- **Déclaré — explication :** [`120901bd`](https://github.com/R0dges/innolab/commit/120901bd3211fb56fa12541eac9e440573325e3d) documente le calcul dans `JUDGING.md`.
- **Observé — tests :** [`82b1a7be`](https://github.com/R0dges/innolab/commit/82b1a7be32fe31702fdd50bb39d1e35b4eb1309e) teste le gagnant clair, la symétrie, les victoires unilatérales et la normalisation des forces.

## Compromis et risque principal

Le modèle est adapté aux duels, mais les graphes déconnectés, le manque de comparaisons, le prior fixe et la conversion vers une échelle 1–5 peuvent donner une précision trompeuse.

## Contrôle qui pourrait réfuter le choix

Tester des graphes déconnectés, des projets rarement comparés et plusieurs valeurs du prior, puis comparer au classement du barème. Ces contrôles n’ont pas été exécutés pendant l’audit.
