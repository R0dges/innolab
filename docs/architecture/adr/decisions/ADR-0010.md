# ADR-0010 — Retirer les abstractions Notils sans usage réel

| Champ | Valeur |
|---|---|
| Domaine | Structure du code |
| Statut documentaire | Vérifié techniquement |
| Statut d’arbitrage | Non arbitré |
| Baseline vérifiée | `develop@2c0b7f82` |

## N0 — En clair

Le scaffold initial séparait l’authentification, le client HTTP et les formulaires dans plusieurs packages génériques. Juryza a supprimé ceux qui compliquaient le parcours sans apporter de réutilisation réelle.

**Impact métier :** le code est plus direct et plus facile à suivre. Il est en revanche moins simple d’extraire ultérieurement l’authentification ou les formulaires pour plusieurs applications.

**Proposition de l’audit :** conserver cette simplification et définir des critères concrets avant de créer un nouveau package partagé.

## N1 — Ce que montre l’historique

- **Observé — état initial :** [`e8b34068`](https://github.com/R0dges/innolab/commit/e8b340680fc28114d6699d9a68e72e11c2a2e02c) contient sept packages : `api-client`, `auth-better-auth`, `auth-core`, `auth-ui`, `config`, `form-builder` et `ui`.
- **Observé — décision réelle :** [`82b1a7be`](https://github.com/R0dges/innolab/commit/82b1a7be32fe31702fdd50bb39d1e35b4eb1309e) supprime les cinq packages d’abstraction et conserve `config` et `ui`.
- **Observé — évolution :** [`86c5a13b`](https://github.com/R0dges/innolab/commit/86c5a13bfe3b6c618f6d299e74d9457a67316107) ajoute ensuite `database`. L’état publié actuel contient donc trois packages, pas deux.
- **Déclaré :** `ARCHITECTURE.md` justifie la suppression par la simplicité du parcours de code.
- **Justification historique :** la justification est écrite dans le même commit que la suppression ; aucune comparaison antérieure des alternatives n’a été trouvée.

## Compromis et risque principal

La navigation et le débogage sont plus simples. Le risque est de recréer plusieurs fois une même responsabilité dans l’application faute de seuil clair pour l’extraire.

## Contrôle qui pourrait réfuter le choix

Rechercher les duplications, les dépendances circulaires et les responsabilités réutilisées par plusieurs applications. Vérifier qu’un nouveau package réduirait réellement le couplage. Ce contrôle n’a pas été exécuté pendant l’audit.
